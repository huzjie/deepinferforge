# 提示词模板：实现算子融合 pass

## 模板

```
请为一张算子级数据流图实现「算子融合」优化 pass，目标模式：
  matmul -> add(bias) -> relu/gelu  =>  fused_gemm_bias_act

要求：
1. 给出模式匹配的伪代码（如何识别候选链）；
2. 说明融合后新节点的输入/属性/dtype 如何继承；
3. 说明如何保持图的拓扑序与下游边不断裂；
4. 指出边界情况（共享输入、多消费者、跨分支）。

输出：可读的伪代码 + 一个 2 条链的示例前后对比。
```

## 为什么这样写

- 「多消费者」是融合最常见的坑：一个中间结果被两个下游用，不能直接折叠。
- 强调「新节点如何继承属性」避免产出 dtype/shape 丢失的坏图。
