# 图优化 Pass

所有 Pass 都只改 IR，不碰任何后端。它们保证语义不变、只做形式重写。

| Pass | 作用 | 可复用要点 |
|------|------|-----------|
| `fusion` | `matmul→add→relu/gelu` 折叠成 `fused_gemm_bias_act` | 融合减少 kernel 启动数与内存往返，是推理加速的第一杠杆 |
| `constfold` | 纯常量算术在编译期求值 | 让后续融合/内存规划能看穿常量子树 |
| `dce` | 删掉不产出 graph output 的节点 | 671B 参数图可以只发「当前请求真正需要」的子图 |
| `memory_plan` | 活跃性分析 + 缓冲复用 | 生命周期不重叠的中间量共享 buffer，压峰值显存 |
| `canonicalize` | 规范化命名/顺序，产出稳定 IR hash | 分布式构建里 IR hash 才能当缓存 key |

## 实现要点（踩坑记录）

- 融合要在 IR 层做「模式匹配 + 节点折叠」：新节点复用最后一个节点的名字与 dtype，
  输入取「上游 matmul 的输入 + add 的非主输入」，避免重新编号导致下游边断掉。
- 内存规划的缓冲复用是**编译期**决策，与运行时 `MemoryPool` 的复用是两回事——前者定
  复用关系，后者按关系实际分配。
