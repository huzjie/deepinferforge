# 架构总览

deepinferforge 是一套「单一 IR、多后端」的跨平台推理编译与运行时参考实现，
拆解 DeepSeek DeepInfer 这类统一推理框架的核心思路：**用一份中间表示，同时编译到
NVIDIA（CUDA）与华为昇腾（CANN）两个算力平台**。

## 分层

```
┌─────────────────────────────────────────────┐
│  engine   InferenceEngine（统一入口）          │
├─────────────────────────────────────────────┤
│  frontend 模型描述 → IR（唯一的表示契约）       │
├─────────────────────────────────────────────┤
│  passes   算子融合 / 常量折叠 / DCE / 内存规划  │  ← 平台无关
├─────────────────────────────────────────────┤
│  backends NVIDIA / Ascend / CPU（共享 oracle） │
├─────────────────────────────────────────────┤
│  codegen  内核源码生成（CUDA / CANN）           │
├─────────────────────────────────────────────┤
│  autotune · quant · scheduler · speculative · kvcache │
└─────────────────────────────────────────────┘
```

## 关键设计决策

1. **IR 是「单一真值」**。跨平台一致性不是靠每个后端各自保证，而是靠「只有一个表示」。
   前端一旦把模型降到 IR，后续所有平台无关优化、所有后端 lowering 都读同一份图，
   因此 NVIDIA 与昇腾的数值结果**必然一致**（参考实现里由共享 oracle 保证）。

2. **图优化在 IR 层做**。算子融合、常量折叠、死代码消除、内存规划都与目标加速器无关，
   所以它们放在 passes 层，先于任何后端执行。

3. **算子抽象层 + 后端代码生成分离**。每个后端只负责「把 IR 节点映射成 kernel」，
   发出的源码不同（CUDA `__global__` vs CANN `__aicore__`），但语义等价。

4. **声明规模与实例化规模解耦**。文档/配置声明 671B MoE、双平台目标，但参考实现只实例化
   微型张量，保证纯 Python 也能在毫秒级跑完整条编译+执行链路。
